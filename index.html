Sweeper: Autonomous Robot Navigation

Python · iRobot Create 3 · CS 1301, Georgia Tech · 2026

The problem. Program a robot to drive from its starting point at (0, 0) to a destination at (0, 120) without hitting anything in the way.

The process. The Create 3 senses obstacles with infrared sensors. My Python program drives forward, checks those sensors, steers around an obstacle when one appears, and then resumes its path toward the goal. It also logs the robot’s position to a CSV file, so I could check where the robot actually went rather than where I assumed it went. I tested with a cardboard box as the obstacle.

The outcome. The lab was graded in a live demo with conceptual questions, so I had to explain why the robot behaves the way it does, not just show it working. That pushed me to understand sensor readings and control flow instead of relying on trial and error.

Find George: One Problem, Two Levels

C · RISC-V assembly · ECE 2035, Georgia Tech · 2026

The problem. Project 1 of ECE 2035, “Find George Possibly Scaled,” asks for a solution to be built at two levels of abstraction.

The process. I first wrote the solution in C, where loops, arrays, and variables keep the logic readable. I am now translating the same logic into RISC-V assembly, where every step becomes explicit register operations, loads, stores, and branches.

The outcome. Seeing both versions side by side showed me what a processor really does with a high-level idea, and it made me more careful about how I structure code before I write it.

Unbeatable Tic-Tac-Toe

C++ · Individual project · April 2025

I built a game that uses artificial intelligence to evaluate possible moves and minimize the opponent’s chances of winning. It uses the minimax algorithm and recursion to simulate every possible sequence of moves, score each end state, and choose the move with the best guaranteed result. Building it taught me how to turn a decision tree into recursive code and how to debug a program whose bugs only appear deep in the recursion.

Car Dealership Negotiation Program

C++ · Individual project · March 2025

A menu-driven program that simulates dealership operations, including inventory management, vehicle sales, and financial tracking. Vectors hold the inventory in memory, and file handling saves it between runs. I split the program into separate features for selling, sorting, organizing data, and calculating monthly earnings so each one could be tested and changed on its own.
